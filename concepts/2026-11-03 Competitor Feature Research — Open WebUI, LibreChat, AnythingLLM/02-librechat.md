## Implementation deep-dives (LibreChat)

All paths are relative to the clone root.

### 1. Tool approval and the HITL pause lifecycle
- `packages/api/src/stream/ApprovalLifecycle.ts` (512 lines) is a guarded state machine for runs in `requires_action`. Pause, resolve and expire all go through the job store's atomic `transitionStatus`. A pause persists the discovered tools, authored skills, activity-phase snapshot, compaction semantic index and context "fading" state, so the resumed run's pruner starts where it left off. The error code is `HITL_ACTION_EXPIRED`. A `persistencePending` flag holds Stop/resume until the paused assistant row is durably written.
- The rules are in `librechat.example.yaml` under `endpoints.agents.toolApproval`: `mode: default|dontAsk|bypass`, `allow`/`deny`/`ask` glob lists on `mcp:<server>:<tool>` (deny always wins), a `reason` template (`"Review {tool} before it runs."`), and `agentModes` for per-agent-row modes (always ask, always approve, once per chat, once then always). `checkpointer: {type: mongo, ttl: 86400}` makes the pause durable.
- Design choice: **pattern rules keyed on a namespaced tool id** let an admin write `deny: ["mcp:*:delete_*"]` once, without classifying each tool. iHub instead classifies each tool by side effect and data flow and treats MCP annotations as untrusted, which is semantically stronger. The two approaches combine well.

### 2. Steering, queued turns, interrupt
- `packages/api/src/stream/SteeringLifecycle.ts` and `packages/api/src/agents/queuedTurns.ts` (1,118 lines), with Mongo schemas `queuedTurn.ts` and `queuedTurnSequence.ts` (`packages/data-schemas/src/schema/`).
- A steer item carries `steerId`, `clientSteerId`, text, files, quotes, `preempt` and `preemptRevision`. Steers are parked durably with their owner (`userId`, `tenantId`) because the claim can outlive the job record. On reconnect the server synthesizes the `on_steer_applied` events missed in the snapshot→subscribe gap, by diffing the fresh content view against the queue. That is the subtle part iHub would need for a multi-tab, reconnect-safe steer UI.

### 3. Resumable generation (job store)
- `packages/api/src/stream/GenerationJobManager.ts` (~9.9k lines) plus `implementations/RedisJobStore.ts`, `RedisEventTransport.ts`, and `InMemory*` fallbacks. `internal/coalescing.ts` coalesces Redis deltas, and `internal/replay.ts` and `checkpoints.ts` replay events on reconnect. `jobStoreCapabilities.ts` and the protocol versions make rolling upgrades safe. This is roughly the same capability as iHub's run ledger and SSE v2, with Redis as the bus.

### 4. Subagents and background tasks
- `packages/api/src/agents/lazySubagents.ts`: subagents are **lazy descriptors**. Only name and description are advertised to the parent model, and the child graph is initialized on the first call. The read and VIEW-ACL check for each subagent are memoized per request. A subagent whose machine is unavailable stays listed with the reason, instead of failing the parent turn. Config: `endpoints.agents.maxSubagents` (default 10, hard cap 50), `subagentActivity` (replay TTL, Redis or memory caches), `fileSharing` (read-only inputs, private outputs until published, manifest TTL).
- `agents/subagentActivity.ts` and `subagentThreads.ts` drive the live child-activity side panel. `agents/tasks.ts` and `backgroundClaims.ts` hold the background task registry, which has durable completion delivery (`readDurableCompletions`), cooperative cancellation, and wake-ups (`backgroundTasks.completionWakeups`, `completionReceiptBatching`). Ready results are delivered together in one synthetic turn.

### 5. MCP On-Behalf-Of and deferred OAuth
- `packages/api/src/mcp/oauth/obo.ts` (483 lines): an injected `OboTokenResolver(user, accessToken, scopes)` and an `UpstreamTokenProvider` that reads the live OIDC session tokens and refreshes them through the IdP refresh grant. `UpstreamTokenTarget {mcpServer, scopes}` is resolved from server config after a trust check ("scopes are not an audience"). Unattended (scheduled) runs need a host-installed `HostUpstreamTokenProviderResolver`. Otherwise they fail closed with `mcp_configuration_missing / unattended_auth_required` (`packages/api/src/schedules/README.md`).
- `packages/api/src/mcp/defer.ts` and `canDeferOAuthSignIn`: when the agent uses deferred tools, the OAuth prompt is shown only when a tool on that server is actually selected, not up front for every attached server.

### 6. Memory with per-agent partitions
- Schema `packages/data-schemas/src/schema/memory.ts` (`userId`, validated `key`, value, token count). `packages/api/src/memory/authorization.ts` adds an optional `agentId` partition and checks VIEW on the agent (`getAgentMemoryPartitionAccess` returns `allowed`, `denied` or `not_found`). `memory/protection.ts` applies the PII filters to memory writes. Config: `memory.{disabled, validKeys, tokenLimit, maxInputTokens, personalize, agent:{enabled, id | provider/model/instructions}}`. A small "memory agent" runs after turns to extract facts automatically, and users edit their memories in Settings → Personalization.

### 7. Agent plugins and hooks
- `packages/api/src/plugins/manifest.ts`: a strict Zod manifest (`$schema`, `name` restricted to `^[a-z0-9.-]`, `version`, `author`, `extensions`), loaded from a deployment directory (`plugins/deployment.ts`, `load.ts`). A plugin bundles skills (`plugins/skills.ts`) and MCP servers (`plugins/mcp.ts`).
- `packages/api/src/agents/hooks/schema.ts`, `executor.ts`, `runtime.ts`, `compatibility.ts`: Claude-Code-compatible hook documents (`hooks: {<Event>: [{matcher, if, hooks:[{type: command|http|mcp|prompt, command, url, headers, allowedEnvVars, server/tool, prompt/model, timeout, once, async, asyncRewake, continueOnBlock}]}]}`). The limits are bounded: 512 handlers in total, a 3,600 s timeout, and 256 headers. Hooks run opt-in, and explicit admin ask/deny rules stay authoritative over them.

### 8. PII and content filters
- `librechat.example.yaml` §`filters` has a per-source policy (`messages`, `prompts`, `agentInstructions`, `conversationStarters`, `conversationTitles`, `feedback`, `skills`, `memories`, `files`), with `fields`, `starterPatterns` (closed catalog, for example `sk_prefix`, `bearer_header`, `api_key_header`) and `customPatterns` (linear-time regex only, rejected at load if unsupported). `action: block` (the default), `audit` (shadow rollout that records findings without raw content), or `redact` (fresh text-only agent chat submissions; the original is kept in an encrypted sidecar). Policy is base-config-only: database overrides cannot weaken it. Enforcement is in `packages/api/src/memory/protection.ts`, `skills/protection.ts` and similar.

### 9. ACL model
- `packages/data-schemas/src/schema/aclEntry.ts` (`principalType` user/group/role/public, `principalId`, `resourceType`, `resourceId`, `permBits`) and `packages/data-provider/src/accessPermissions.ts` (`PermissionBits VIEW=1, EDIT=2, DELETE=4, SHARE=8, VIEW_INSIGHTS=16`; roles `agent_viewer/editor`, `promptGroup_*`, `mcpServer_*`, `skill_*`, `remoteAgent_*`, `codeEnvironment_*`). There is one middleware (`packages/api/src/acl/middleware.ts`, `accessControlService.ts`) and an audit trail (`acl/audit.ts`). Every user-created resource type gets sharing through the same code path.

### 10. Scheduled chats (for comparison)
- `packages/api/src/schedules/` (engine, cadence, capacity, readiness, authorization/*). The notable idea is **unattended readiness preflight**. Before a schedule is created and before each dispatch, LibreChat checks that every MCP server of the agent graph can connect without a browser. `mcp_reauth_required`, `mcp_configuration_missing` or `mcp_permission_denied` disables the schedule immediately, and failure records hold only server names and status codes. Readiness checks use a separate bounded pool so slow MCP servers cannot use up generation capacity.

## Ideas worth adopting for iHub (ranked)

1. **Ship the steer/queue UI on the existing server seam** (small effort, high value). `steering.js` and `POST /runs/:id/human-events` already exist, but nothing in the client calls `sendHumanEvent`. Let users type while a run streams: queue the message, show it as a "pending steer" chip, and inject it at the next step boundary. Add LibreChat's reconnect-gap diff (synthesize "applied" for steers applied while disconnected) and consider persisting the queue so it survives a worker restart.
2. **Long-term user memory for chat apps** (medium effort, high value). Reuse `memoryService.js` with a new `{kind:'user', userId}` scope (optionally partitioned by app), plus a Settings → Memory page to view, edit and delete entries. Add an opt-in post-turn extraction step, which iHub already has as the `memory-compose`/`memory-finalize` pattern for agents. Admin knobs: `validKeys`, `tokenLimit`, per-app enable.
3. **MCP `sso` / OBO auth mode** (medium effort, high enterprise value). Generalize `iFinderTokenProvider` (RFC 8693 / jwt-bearer) into an MCP install auth mode `sso`, so MCP servers behind the same IdP get a per-user exchanged token with no connect click. Copy LibreChat's fail-closed rule for scheduled tasks when no renewable upstream token exists.
4. **Input DLP / secret filter with `audit` shadow mode** (medium effort, high value for regulated customers). Per surface (chat input, prompts, skills, memory, uploads): starter detectors for API keys and bearer tokens, admin regexes, and `block|audit` (redact later). Audit-first rollout is the key design idea. It also fits `docs/pii-data-handling.md`.
5. **Model pricing and cost** (small to medium effort). Add optional `pricing {inputPerMTok, outputPerMTok, cacheRead, cacheWrite}` to `modelConfigSchema.js` (needs a migration only if defaults are seeded). Show cost per chat next to the existing context indicator and per app, user or group in Usage Reports. Admins ask for chargeback.
6. **Office previews in the Artifacts panel** (small effort). `mammoth` and `xlsx` are already client dependencies, so render DOCX→HTML and XLSX→table, and PPTX at least as slide text. That closes the documented "no preview" gap in `docs/artifacts.md`.
7. **Admin glob rules on top of tool-approval classes** (small effort). Add `toolApproval.allow/deny/ask: ["mcp:<server>:delete_*"]` (deny wins) as a coarse override layer, and optionally per-app approval modes.
8. **Background tool calls with wake-up** (large effort). Let long tools (A2A tasks, long MCP calls, workflow runs) run detached and post the result back into the same chat as a synthetic turn. The scheduled-task and durable-run infrastructure is most of the plumbing.
9. **Lazy tool discovery (`tool_search`)** for apps with many MCP tools (medium effort). Advertise only server names and descriptions, and let the model search and load tool schemas on demand. Pair it with deferred OAuth: ask for MCP sign-in only when that server's tool is actually needed.
10. **Admin-configurable hooks** (Claude-Code-compatible `PreToolUse`/`PostToolUse` with HTTP/command handlers, `matcher`, `timeout`) mapped onto the existing `preTool`/`postTool` loop seams. This is an enterprise policy and integration point (for example a central DLP or approval webhook). HTTP hooks must use `httpFetch()` for the SSL whitelist.
11. **Chat-list ergonomics**: pin chats, filter by app/date/files/shared, global keyboard shortcuts, long paste as attachment. Each is small.
12. **User-built apps with ACL sharing** (large effort; product decision). LibreChat lets any user build an agent and share it (VIEW/EDIT/SHARE) or publish it to a marketplace category. iHub already has the sharing UX for prompts, skills and projects, so a "user apps" tier would reuse it.
13. Lower priority: Langfuse exporter (OTel already covers most of it), RTL layout, a forced-ephemeral retention switch, passkeys/2FA for local accounts.
