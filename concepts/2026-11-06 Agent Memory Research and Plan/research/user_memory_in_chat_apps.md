# User memory and agent memory in end-user chat apps and agent harnesses (state as of 2026-11-06)

Scope note: this covers OpenClaw, Hermes Agent, LibreChat, Open WebUI, AnythingLLM, plus reference products (ChatGPT, Claude.ai, Claude Code, Microsoft 365 Copilot, Gemini, Cursor, Windsurf). Primary sources were official docs/help centers and source code where reachable. Two official pages could not be fetched directly (OpenAI's Memory FAQ and Cursor's removed Memories doc return 403/404 to this environment); where I rely on a search-engine summary of an official page or on a secondary source, I say so. GitHub API access to the openclaw, hermes-agent, LibreChat, open-webui and anything-llm repos was blocked in this session, so release dates for some open-source features come from secondary sources and are flagged.

## Per-system profiles: what is remembered, how it is created, stored, retrieved, scoped, controlled

### Takeaway
The open-source harnesses split cleanly into two camps: **file/markdown-first agent harnesses** (OpenClaw, Hermes Agent, Claude Code) that inject a curated `MEMORY.md`/`USER.md` into every system prompt and bolt search on top, versus **database-backed chat apps** (LibreChat, Open WebUI, AnythingLLM) that keep per-user key/value or sentence memories in the app DB (Open WebUI additionally embeds them in a per-user vector collection) and inject a bounded block into the system prompt. The commercial assistants (ChatGPT, Claude.ai, Copilot, Gemini) all converge on the same user-facing shape: automatic extraction during chat, a browsable list of memories with edit/delete, a global on/off, a per-chat opt-out ("Temporary"/"Incognito"), and explicit rules about sensitive data.

### Cited Findings

#### OpenClaw (open-source personal agent; formerly Clawdbot / Moltbot)
- Naming history (secondary sources only): ClawdBot was first published on GitHub by Peter Steinberger in November 2025; it was renamed Moltbot in late January 2026 after Anthropic's legal team requested a name change because "Clawd" was too close to "Claude", then became OpenClaw on January 30, 2026 — [DEV Community](https://dev.to/zacvibecodez/clawdbot-vs-moltbot-vs-openclaw-are-they-the-same-thing-31ff); [eastondev rename history](https://eastondev.com/blog/es/posts/ai/20260204-openclaw-rename-history/); [Zilliz FAQ](https://zilliz.com/ai-faq/is-openclawmoltbotclawdbot-the-same-as-clawdbot). I found no official changelog confirming these dates.
- (1) What is remembered / (3) storage — plain markdown files in the workspace (default `~/.openclaw/workspace`): `USER.md` (optional; "stable preferences, communication style, relationships, and active-project context, written as directives", loaded at session start with its own small budget), `MEMORY.md` ("curated long-term, non-profile facts and decisions", loaded at session start), daily notes `memory/YYYY-MM-DD.md` or `memory/YYYY-MM-DD-<slug>.md` ("indexed for search, not injected every turn"; today's and yesterday's notes load on a bare `/new` or `/reset`), optional `DREAMS.md` (dream diary), per-person profiles under `users/<profile-id>/USER.md`, and import folders `memory/imports/codex/`, `memory/imports/claude-code/`, `memory/imports/hermes/` — [OpenClaw docs: Sessions and memory](https://docs.openclaw.ai/concepts/memory.md).
- The docs' framing of what belongs in memory: "Durable facts, stable preferences, and standing decisions" plus "action-sensitive notes" (approval requirements, temporary constraints, handoffs, expiry conditions, actions to avoid); and the explicit caveat that "Memory informs behavior but does not enforce policy. Use approval settings, sandboxing, and scheduled tasks for hard controls." — [OpenClaw docs: memory](https://docs.openclaw.ai/concepts/memory.md).
- (2) Creation — the model writes to the files itself ("The model only remembers what is saved to disk"); plus a **pre-compaction memory flush**: "Runs a silent turn before compaction to save important context. On by default", disabled with `agents.defaults.compaction.memoryFlush.enabled: false`; during the flush, `write` appends only to the daily note; requires a writable workspace, and a failed flush does not block compaction — [OpenClaw docs: memory](https://docs.openclaw.ai/concepts/memory.md).
- (4) Retrieval — `USER.md` and `MEMORY.md` are injected at session start; if `MEMORY.md` exceeds the bootstrap budget "the disk file stays intact but the injected copy is truncated" (check with `/context list`, `/context detail`, or `openclaw doctor`). Tools: `memory_search` ("finds notes by meaning and keywords", can also return session-transcript hits), `memory_get` (reads a file or line range), `sessions_search` / `sessions_history` for transcripts. "Automatic project recall" has a one-second preparation budget; if it expires the Gateway logs `project memory recall skipped` — [OpenClaw docs: memory](https://docs.openclaw.ai/concepts/memory.md).
- Search backend — hybrid vector + keyword search once an embedding provider is configured; default provider OpenAI, set `memory.search.provider` explicitly for Gemini, Voyage, Mistral, Bedrock, DeepInfra, local GGUF, Ollama, LM Studio, GitHub Copilot, or a generic OpenAI-compatible endpoint; engines: Builtin (SQLite, default), Honcho, LanceDB (`memory-lancedb`); PostgreSQL needs `unaccent`, `pg_trgm`, `vector`; keyword-only via `memory.search.provider: "none"` — [OpenClaw docs: memory](https://docs.openclaw.ai/concepts/memory.md). The search-engine summary of the same page adds that search is "enabled automatically" when an OpenAI, Gemini, Voyage or Mistral key is configured — [docs.openclaw.ai (search summary)](https://docs.openclaw.ai/concepts/memory/index.html).
- Trust — "Untrusted files, and remote files without a valid read-source identity, are excluded. The Gateway logs one warning per excluded file" — [OpenClaw docs: memory](https://docs.openclaw.ai/concepts/memory.md).
- (6) CLI controls — `openclaw memory status`, `openclaw memory search "query"`, `openclaw memory index --force`, `openclaw memory reset` (clears derived data, keeps files), `openclaw memory rem-backfill`, `openclaw plugins reload memory-core`, `openclaw doctor` — [OpenClaw docs: memory](https://docs.openclaw.ai/concepts/memory.md).
- (5) Scoping — one workspace per agent; multi-user profiles via `users/<profile-id>/USER.md`; a third-party analysis reports "Projects share one memory store with no boundary, so answers can include details from unrelated projects" — [db0.ai "Why OpenClaw forgets" (2026-03-19)](https://www.db0.ai/blog/why-openclaw-forgets).
- (8) Known problems (secondary/community sources): rules given only in chat are lost at compaction (an example cited: an agent that obeyed "don't do anything until I confirm" until compaction dropped it, then bulk-deleted emails); config/bootstrap files have character limits ("20,000 per file, 150,000 total") and content past the limit is cut silently, shown as `TRUNCATED` in `/context list`; sub-agents receive `AGENTS.md`, `TOOLS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md` but not `MEMORY.md`; daily logs are only reachable via search; compaction summaries lose exact wording — [db0.ai](https://www.db0.ai/blog/why-openclaw-forgets). Multiple vendor blogs (Supermemory, besthub, markaicode) repeat the same list; one notes the memory docs changed in October 2026 to add hybrid search and the "dreaming" sweep, so older advice is stale — [Supermemory blog](https://supermemory.ai/blog/why-everyone-is-complaining-about-openclaws-memory-it-sucks-and-why-supermemory-fixes-it/); [besthub](https://www.besthub.dev/articles/why-openclaw-s-memory-fails-and-how-to-fix-it-5-root-causes-practical-solutions-e51ea4aa82cb). These are vendor-interested sources.

#### Hermes Agent (Nous Research)
- Launch: Product Hunt lists the launch as February 26, 2026; MIT licensed; secondary sources report v0.9.0 on April 13, 2026 and v0.20.0 on August 3, 2026 — [Product Hunt](https://www.producthunt.com/products/hermes-4/launches); [hashnode v0.11 deep dive](https://hashnode.com/posts/hermes-agent-v0110-deep-dive-the-open-source-ai-agent-that-hit-105k-stars-in-7-weeks/69eeafeca924ccdc3652c5d6); [runtimewire](https://runtimewire.com/article/nous-research-hermes-agent-v0200-voice-a2a); [GitHub README](https://github.com/NousResearch/hermes-agent) (README confirms MIT and "FTS5 session search with LLM summarization for cross-session recall", "Honcho dialectic user modeling", but gives no release date).
- (1)/(3) Two markdown stores in `~/.hermes/memories/`: `MEMORY.md` — "the agent's own notes (environment facts, conventions, lessons)", limit 2,200 characters (~800 tokens); `USER.md` — "the user profile (preferences, communication style)", limit 1,375 characters (~500 tokens). Memory is scoped per profile (`~/.hermes/profiles/<name>/memories/`). Session history is SQLite at `~/.hermes/state.db` — [Hermes docs: Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- (2) Creation — the agent calls a memory tool with actions `add`, `patch` (replaces one exactly-matched span), `remove` (substring match); `replace` was removed and now errors pointing to `patch`; every call needs a top-level `target` of `"memory"` or `"user"`; there is no read action. "Memory does not auto-compact. A write that exceeds the limit returns an error, and the agent must consolidate or remove entries and retry in the same turn." Exact duplicates are rejected. Entries are scanned "for injection and exfiltration patterns and for invisible Unicode" and blocked if matching — [Hermes docs: Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- Also a **background self-improvement review** after a turn that may save memories or update skills, configured under `auxiliary.background_review` (`provider`, `model` default `auto`, `enabled`, `max_input_tokens`, `extra_tools`, `defer` = `auto`|`never`, `defer_max_age_s` default 1800, `reasoning_effort`); frequency tuned by `memory.nudge_interval` and `skills.creation_nudge_interval`; notifications via `display.memory_notifications` (`off`, `on`, `verbose`) — [Hermes docs: Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory). The README describes this as memory "updated through periodic nudges" — [GitHub README](https://github.com/NousResearch/hermes-agent).
- (4) Retrieval — "Entries load from disk at session start and are injected as a frozen snapshot. Mid-session changes are saved immediately but appear only in the next session." The header shows store name, usage percentage and character counts; entries separated by `§`. Separate `session_search` tool does FTS5 full-text search over past CLI and messaging sessions in SQLite, returning raw messages with "no LLM summarization and no truncation" and no LLM calls — [Hermes docs: Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory). (The README says session search has "LLM summarization"; the docs page says it does not — conflict noted.)
- Config keys: `memory.memory_enabled` (default `true`), `memory.user_profile_enabled` (default `true`), `memory.memory_char_limit` (2200), `memory.user_char_limit` (1375), `memory.write_approval` (default `false`), `memory.prefetch_spill_enabled` (default `false`), `memory.provider` (external provider), `skills.write_approval` (default `false`) — [Hermes docs: Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- (6) User controls — with `write_approval: true` writes are staged: `/memory pending`, `/memory approve <id|all>`, `/memory reject <id|all>`, `/memory approval on|off`; `/journey` (aliases `/learning`, `/memory-graph`) and `hermes journey list|delete|edit` review learned skills and memory; `/new` refreshes the snapshot; `hermes memory setup` / `hermes memory status` for external providers — [Hermes docs: Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- Skills as procedural memory — all skills live in `~/.hermes/skills/` as `SKILL.md` with YAML frontmatter (`name`, `description`, `version`, `platforms`, `metadata.hermes.*`) and sections When to Use / Procedure / Pitfalls / Verification, optional `references/`, `templates/`, `scripts/`, `examples/`, `assets/`; the agent manages them via the `skill_manage` tool (`create`, `patch`, rewrite, `delete`, `write_file`, `remove_file`); the system prompt asks it to save "non-trivial, multi-step workflows, approaches that worked after errors, and corrections from the user"; skills should capture "lessons, not logs"; an advisory linter flags incident-log shape, >60 reference files, or a body over ~24k chars but never blocks; `skills.write_approval: true` stages writes under `~/.hermes/pending/skills/` reviewed with `/skills pending|diff|approve|reject|approval`; `hermes curator lock <skill>` makes a skill read-only to agent writes; `skills.guard_agent_created` is a content scanner — [Hermes docs: Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).
- Honcho (optional external user model) — plugin from Plastic Labs, "AI-native memory backend that adds dialectic reasoning and deep user modeling"; opt-in via `hermes plugins install honcho`, `hermes memory setup` or `memory.provider: honcho` plus `HONCHO_API_KEY`; in `hybrid`/`context` modes it injects every turn a base context (session summary, user representation, peer cards) refreshed per `contextCadence` (default 1) and a "dialectic supplement" capped by `dialecticMaxChars` (default 600) refreshed per `dialecticCadence` (default 2); `sessionStrategy`: `per-directory` (default), `per-repo`, `per-session`, `global`; data is stored server-side (cloud at honcho.dev or self-hosted) — [Hermes docs: Honcho](https://hermes-agent.nousresearch.com/docs/user-guide/features/honcho).
- (8) Known problems (community/vendor sources): files stay empty after quiet sessions because memory is "agent-curated, not a recorder"; the 2,200-char cap "silently drops facts with no signal to the caller"; stale facts resurfacing weeks later; cross-profile contamination when memories are shared between agents; manual cleanup burden — [Vectorize](https://vectorize.io/articles/hermes-agent-memory-not-working); [aiweekly alert](https://aiweekly.co/alerts/hermes-memory-cap-causes-silent-fact-loss-in-agents). Both are vendor-interested.

#### LibreChat
- (1)/(3) "Memory is a small store of facts about you, saved as key/value pairs. It is not a search over chat history." Stored in the app database per user; agents can have an isolated partition — [LibreChat docs: User Memory](https://www.librechat.ai/llms.mdx/docs/features/memory); source: agents with `memory_scope: 'agent'` get their own partition, otherwise "memory is shared in the personal pool" — [LibreChat source packages/api/src/agents/memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- (2) Creation — two paths. (a) Manual tool use: the user enables **Memory** under **Tools** in the **+** palette; the model gets `set_memory` and `delete_memory` and uses them "only when you ask it to remember, update, or forget something"; saves show as "Saved memory"/"Deleted memory" steps. (b) Optional **memory agent**: "a background agent that reviews exchanges and saves facts without being asked. It is opt-in, needs its own model, and is enabled by the admin" — [LibreChat docs: User Memory](https://www.librechat.ai/llms.mdx/docs/features/memory). The default agent instructions in source say "Use the `set_memory` tool to save important information about the user, but ONLY when the user has requested you to remember something", "NEVER store information just because the user mentioned it in conversation", "When in doubt, and the user hasn't asked to remember or forget anything, END THE TURN IMMEDIATELY", with trigger phrases "Remember [that] [I]...", "Forget [that] [I]...", "Delete the memory about..." — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- Memory agent runtime: "the memory agent runs at the start of every chat request, alongside the main response. It gets until the main response finishes plus up to 3 seconds. If it is still running after that, its result is dropped" — [LibreChat config docs: memory](https://www.librechat.ai/llms.mdx/docs/configuration/librechat_yaml/object_structure/memory). Default model `gpt-4.1-mini`, temperature 0.4, `recursionLimit: 3`; `set_memory` writes are serialized so parallel calls cannot exceed the token limit; token counting with `o200k_base`; `MEMORY_KEY_CHAR_LIMIT` = 1000 — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- (4) Injection — "The entire store is added to the context of every new message, so it suits a handful of durable facts" — [LibreChat docs](https://www.librechat.ai/llms.mdx/docs/features/memory). Source: system prompt gets the memory instructions then `# Existing memory about the user:`; with a token limit the processor block is `# Memory Status:` (usage, limit, remaining) then `# Existing memory:`; on Bedrock the block is prepended to the first user message — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- Config block in `librechat.yaml` (exact keys): `disabled` (Boolean, default `false`), `validKeys` (array of strings; restricts key names), `tokenLimit` (number; caps total tokens of all memories per user; saves over the cap are rejected), `charLimit` (number, default `10000`, per entry), `maxInputTokens` (number, default `12000`, recent-chat tokens sent to the memory agent; truncated from the beginning), `personalize` (Boolean, default `true`; when true users can opt out), `messageWindowSize` (number, default `5`; messages reviewed per request, only when `agent.enabled`), `agent` (object: `enabled`, `id` **or** `provider` + `model` + optional `instructions` + `model_parameters`). Custom `instructions` "replace the default memory rules" and are recommended with `validKeys`. Memory is active only when a `memory` block exists — [LibreChat config docs: memory](https://www.librechat.ai/llms.mdx/docs/configuration/librechat_yaml/object_structure/memory). Example from the docs:
  ```yaml
  memory:
    disabled: false
    validKeys: ['user_preferences', 'conversation_context', 'personal_info']
    tokenLimit: 2000
    charLimit: 10000
    maxInputTokens: 12000
    personalize: true
    messageWindowSize: 5
    agent:
      enabled: true
      provider: 'openAI'
      model: 'gpt-4'
      instructions: 'You are a helpful assistant that remembers user preferences and context.'
  ```
- (6) UI — **Memories** side panel lists entries, filterable by key/value/agent; **Create Memory (+)** (keys must be lowercase letters and underscores, unique); edit/delete any entry; a usage badge when an admin sets a limit; "Memory Storage Full" when full. Opt-out: the **Use memory** button in the panel or **Reference saved memories** under **Settings > Data & Privacy**; when off, memories aren't injected and the tool isn't offered, entries are kept; the toggle appears only if `personalize` allows — [LibreChat docs](https://www.librechat.ai/llms.mdx/docs/features/memory).
- (7) Admin — off until an admin adds the `memory` block; roles can limit create/update (tools require `USE` + `CREATE`/`UPDATE` permissions); agents can be set "Keep memories separate for this agent"; agent-scoped entries become inaccessible if the user loses access to the agent (deletable if the agent was removed) — [LibreChat docs](https://www.librechat.ai/llms.mdx/docs/features/memory); [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- Version introduced: not confirmed. `v0.8.2-rc2` release notes mention "Add Memory Configuration Options for CI unit tests", so the feature predates that — [LibreChat changelog v0.8.2-rc2](https://www.librechat.ai/changelog/v0.8.2-rc2). The `v0.7.9` changelog page does not mention memory — [LibreChat changelog v0.7.9](https://www.librechat.ai/changelog/v0.7.9).
- (8) Known problems: the docs' troubleshooting list (memory not configured, `disabled` not false, agent/model unavailable, user toggle off, custom endpoint `provider` must exactly match the endpoint `name`, token limit exceeded, conflicting memories) — [LibreChat docs: memory](https://librechat.ai/docs/features/memory). I found no GitHub issue threads via search.

#### Open WebUI
- (1)/(3) Each memory has a `type` (`user` or `context`) and an optional `path` for grouping; stored in the Open WebUI database table (`Memories` model: id, user id, content, type, path, timestamps, metadata) **and** embedded into a per-user vector collection `user-memory-{user_id}` — [Open WebUI docs: Memory](https://docs.openwebui.com/features/chat-conversations/memory.md); [open-webui source routers/memories.py](https://raw.githubusercontent.com/open-webui/open-webui/main/backend/open_webui/routers/memories.py).
- (2) Creation — three paths: manual entry at **Settings > Personalization > Memory**; model tool calls when Native Function Calling is enabled (`add_memory`, `update_memory` (batch add/replace/move/remove), `replace_memory_content`, `delete_memory`, `search_memories` (5 results default), `list_memories`, `list_memory_paths`, `read_memory_path`); and optional background review ("the chat's model periodically reviews recent conversation and can add, replace, move, or remove memories") — [Open WebUI docs: Memory](https://docs.openwebui.com/features/chat-conversations/memory.md). The docs say Native Tool Calling upgraded memory "from a passive injection mechanism to an active, model-managed 'long-term memory'" and that memory tool calls require a streaming format that follows the OpenAI schema (endpoints omitting the `index` field on streamed tool calls, like Google's OpenAI-compat layer, can produce blank replies) — [Open WebUI docs: Memory](https://docs.openwebui.com/features/chat-conversations/memory).
- (4) Retrieval — "By default, stored memories are injected into the system context on every turn", with separate budgets `MEMORIES_CONTEXT_CHAR_LIMIT` (default `2000`) and `MEMORIES_USER_CHAR_LIMIT` (default `2000`); the `POST /query` endpoint embeds the query and searches `user-memory-{user_id}` (k defaults to 1, filtered by `rag.relevance_threshold` when > 0); `/search`, `/paths`, `/path` are DB lookups without vectors — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/memory.md); [memories.py](https://raw.githubusercontent.com/open-webui/open-webui/main/backend/open_webui/routers/memories.py).
- Env vars (exact): `ENABLE_MEMORIES` (default `True`), `USER_PERMISSIONS_FEATURES_MEMORIES` (default `True`), `ENABLE_MEMORY_SYSTEM_CONTEXT` (default `True`), `ENABLE_MEMORY_BACKGROUND_REVIEW` (default off), `MEMORIES_REVIEW_INTERVAL_TURNS` (default `10`), `MEMORIES_CONTEXT_CHAR_LIMIT` (`2000`), `MEMORIES_USER_CHAR_LIMIT` (`2000`) — [Open WebUI docs: Memory](https://docs.openwebui.com/features/chat-conversations/memory.md).
- (5)/(7) Scope and admin — memories are per user account, never shared; global toggle at Settings > Admin > General > Features > Memories (when off: Personalization tab hidden, API endpoints blocked, no injection, no memory tools); per-role/group permission at Admin Panel > Users > Permissions > Features > Memories (users without it get 403 and no injection; admins exempt); Memory capability per model under Workspace > Models > Edit > Builtin Tools (on by default); v0.12.4 (2026-10-25) hides the Memory capability in the model editor while the feature is off instance-wide — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/memory.md); [open-webui CHANGELOG.md](https://raw.githubusercontent.com/open-webui/open-webui/main/CHANGELOG.md).
- (6) User controls — view/add/edit/delete at Settings > Personalization > Memory; "clear your entire memory bank at any time"; users can review and delete model-added memories — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/memory.md).
- Feature age: a 2024 issue on v0.1.125 ("Unable to use open-webui without setting up Memory") shows the Personalization/Memory feature already existed then — [open-webui issue #2408](https://redirect.github.com/open-webui/open-webui/issues/2408).
- Community extension: "Adaptive Memory" (gramanoid/adaptive_memory_owui; v3.0/v3.1 May 2025) is a Function (not a Tool) pasted into Functions; v3.1 added confidence scoring/filtering, flexible embedding providers and Prometheus metrics; users reported extraction errors and that v3 did not work with the Gemini API — [r/OpenWebUI v3.1 thread](https://redlib.hbubli.cc/r/OpenWebUI/comments/1kegqvh/adaptive_memory_v31_github_release_and_a_few); [openwebui.com function page](https://openwebui.com/f/alexgrama7/adaptive_memory_v2). A mem0 filter that injects retrieved memories into the system message is another community option — [mem0-owui](https://gh.r-mj.com/cloudsbird/mem0-owui).
- (8) Known problems: quality "depends heavily on the model. Small local models may store or retrieve memories inconsistently"; the OpenAI-schema streaming requirement above — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/memory.md).

#### AnythingLLM
- Shipped in v1.13.0 (release notes: "automatic memory extraction and personalization"; "A background job pulls memories from conversations into a memory bank"; "Memories are injected into the system prompt") — [newreleases.io v1.13.0](https://newreleases.io/project/github/Mintplex-Labs/anything-llm/release/v1.13.0). Date: MajorGeeks lists 06/06/26 (likely June 6, 2026; third-party) — [MajorGeeks](https://www.majorgeeks.com/files/details/anythingllm.html). The docs banner now shows v1.14.2 — [docs.useanything.com](https://docs.useanything.com/).
- (1)/(5) Two scopes: workspace memories (max 20 per user per workspace) and global memories (max 5 per user); each user's memories are private; memories can be moved between scopes; "A full destination blocks adds and moves" — [AnythingLLM docs: Memories](https://docs.anythingllm.com/features/memories).
- (2) Creation — manual (+ button, "a one-sentence fact") and **Automatic Memory Extraction** (separate toggle, on by default): an *Observer* proposes up to 3 candidate facts per run with confidence; a *Reflector* classifies scope, dedupes, merges updates, filters low-confidence candidates "unless they are clear identity facts"; runs every 3 hours (`MEMORY_EXTRACTION_INTERVAL`), skips workspaces active within the idle threshold (`MEMORY_IDLE_THRESHOLD_MS`, default 1200000 ms = 20 min), needs at least 5 unprocessed chats per workspace, uses the workspace chat model → agent model → system default, and requires tool calling — [AnythingLLM docs: Memories](https://docs.anythingllm.com/features/memories).
- (4) Injection — appends a `## Things I Remember About You` section to the workspace system prompt containing all global memories and the 5 most relevant workspace memories (scored against the message and recent history; falls back to 5 newest); applies to regular, streamed, agent and API chats — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).
- (6)/(7) Controls — chat settings icon > **Memories** > **Enable Personalization** (off by default; only admins in multi-user mode); each card has Edit / Delete / Move; "no user can see another's"; when multi-user mode is enabled on an existing instance, prior memories move to the new admin account — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).
- Sensitive-data guidance: "Memory content is sent to your LLM provider as part of the system prompt. Don't store passwords, API keys, or sensitive personal data." — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).

#### ChatGPT (OpenAI) — reference

## Which systems use file-based (markdown) memory vs database/vector memory, and what trade-offs do they report?

### Takeaway
File-based: OpenClaw (`MEMORY.md`, `USER.md`, daily notes; SQLite only for the search index and dreaming state), Hermes Agent (`MEMORY.md`/`USER.md`; SQLite for sessions), Claude Code (`MEMORY.md` + topic files, CLAUDE.md), Windsurf rules. DB/vector: LibreChat (DB key/value), Open WebUI (DB rows + per-user vector collection), AnythingLLM (DB with scoring), and all hosted assistants (Copilot stores memories in the user's Exchange mailbox). The documented trade-offs are: files are inspectable/editable/portable and trivially versioned, but they hit injection budgets, truncate silently, need manual curation, and lose anything never written down; DB/vector stores scale and allow relevance ranking but add an embedding dependency, a per-request extraction cost, and model-quality sensitivity.

### Cited Findings
- OpenClaw keeps markdown as the source of truth and uses SQLite only for "derived data" (`openclaw memory reset` "clears derived data and keeps memory files and sessions"); dreaming "machine state ... lives in SQLite-backed plugin state" and `MEMORY.md` preimages are saved to SQLite before a rewrite — [OpenClaw memory](https://docs.openclaw.ai/concepts/memory.md); [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- OpenClaw documents the file trade-off explicitly: oversized `MEMORY.md` is truncated in context while the disk file stays intact — [OpenClaw memory](https://docs.openclaw.ai/concepts/memory.md); third parties list silent truncation at 20,000 chars/file and 150,000 total, no automatic retrieval of daily logs, and the need for manual `/new`, cron pruning and hand-sectioned files as "too much overhead for a memory system" — [db0.ai](https://www.db0.ai/blog/why-openclaw-forgets).
- Hermes documents hard caps (2,200 / 1,375 chars) with no auto-compaction and an error on overflow that the agent must resolve in the same turn; its rationale for FTS session search instead of vectors: "no LLM calls and ... not token-limited in total capacity. Memory is for always-in-context facts; session search is for recalling specifics" — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory). Community reports: the cap "silently drops facts" and files stay empty after quiet sessions — [aiweekly](https://aiweekly.co/alerts/hermes-memory-cap-causes-silent-fact-loss-in-agents); [Vectorize](https://vectorize.io/articles/hermes-agent-memory-not-working).
- Claude Code: "Auto memory files are plain markdown you can edit or delete at any time"; "Auto memory is machine-local ... not shared across machines or cloud environments"; index limited to 200 lines/25 KB with an automatic reminder/error to rewrite — [Claude Code memory](https://code.claude.com/docs/en/memory).
- LibreChat (DB key/value) states the opposite trade-off: "The whole store is sent with each request, so it should stay small"; "Only saved entries are recalled; chat history is not searched" — [LibreChat memory docs](https://www.librechat.ai/llms.mdx/docs/features/memory).
- Open WebUI (DB + vectors): `/query` embeds the query and searches `user-memory-{user_id}`; on an embedding-dimension mismatch the code reindexes that user's vectors; an admin `/reindex` rebuilds all users — [memories.py](https://raw.githubusercontent.com/open-webui/open-webui/main/backend/open_webui/routers/memories.py). Reported trade-off: small local models "may store or retrieve memories inconsistently" — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/memory.md).
- AnythingLLM (DB with scoring/rerank, no vector collection described): more than 5 workspace memories are "scored against your message and recent history. If scoring fails, the 5 newest are used" — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).
- Microsoft 365 Copilot stores memories "in the user's Exchange mailbox in a hidden folder" so they inherit mailbox security/compliance (Customer Lockbox, encryption at rest) but not Purview retention policies — [Microsoft Learn](https://learn.microsoft.com/copilot/microsoft-365/copilot-personalization-memory).
- Claude.ai now stores memory "as short topic files" (per Anthropic's wording) that users can view/edit/delete per topic — [Anthropic blog](https://claude.com/blog/claudes-memory-works-everywhere-and-you-decide-whats-in-it).

### Inferences
- Portability follows the file camp: OpenClaw ships import folders for Codex, Claude Code and Hermes memories, and Hermes imports OpenClaw memories into `MEMORY.md`/`USER.md` ([OpenClaw memory](https://docs.openclaw.ai/concepts/memory.md); [Hermes README](https://github.com/NousResearch/hermes-agent)); the hosted products achieve the same with "paste a prompt-generated summary" import flows.
- A hybrid is emerging on both sides: file-first harnesses add SQLite/vector indexes for search (OpenClaw, Hermes FTS5), and DB-first apps add relevance ranking (AnythingLLM) or vectors (Open WebUI) on top of a bounded always-on block.

### Gaps
- No quantitative benchmarks comparing the two approaches from any of the projects themselves; vendor blogs claiming benchmark wins were excluded as interested parties.

## Which use an LLM tool call ("save memory") vs post-hoc extraction, and which combine both?

### Takeaway
Tool-call only: Hermes built-in memory (`add`/`patch`/`remove`), Claude Code auto memory (file writes during the session), OpenClaw's in-session writes. Post-hoc/background extraction only: AnythingLLM (Observer/Reflector job every 3 h on idle workspaces), Claude.ai legacy (24-hour summary). Both: LibreChat (explicit `set_memory`/`delete_memory` tool plus an optional per-request memory agent), Open WebUI (model tools plus optional background review every N turns), OpenClaw (in-session writes + pre-compaction flush + nightly Dreaming consolidation), Hermes (tool + post-turn background review), ChatGPT/Copilot/Claude current (automatic save during chat plus explicit "remember this").

### Cited Findings
- LibreChat: tools `set_memory`/`delete_memory` used "only when you ask"; the optional agent "reviews exchanges and saves facts without being asked"; the agent runs "at the start of every chat request, alongside the main response" with a 3-second grace after the main response — [LibreChat memory docs](https://www.librechat.ai/llms.mdx/docs/features/memory); [LibreChat config docs](https://www.librechat.ai/llms.mdx/docs/configuration/librechat_yaml/object_structure/memory).

- AnythingLLM: no tool; a background job every 3 hours, only for workspaces idle ≥ 20 minutes with ≥ 5 unprocessed chats; Observer proposes ≤ 3 candidates with confidence, Reflector dedupes/merges/classifies — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).
- Hermes: memory tool with `add`/`patch`/`remove` during the session plus "a background self-improvement review that runs after a turn and may save memories or update skills" — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).

### Inferences
- Projects that start tool-only (LibreChat's default prompt forbids saving unrequested facts) add extraction as an admin-gated option because explicit-only memory stays empty; projects that start extraction-only (ChatGPT) add approval/limits because extraction over-saves. Hermes' `write_approval` staging and AnythingLLM's confidence-filtered Reflector are the two mid-points.

## How does OpenClaw's memory and "Dreaming" consolidation actually work?

### Takeaway
Dreaming is a `memory-core` plugin cron sweep (default daily 03:00) with three ordered phases — light (stage/dedupe short-term signals), REM (theme/reflection summaries) and deep (score and promote into `MEMORY.md`); only deep writes durable memory, and promotion is gated by weighted relevance/frequency/query-diversity/recency scores and `minScore`/`minRecallCount`/`minUniqueQueries` thresholds, with every sweep narrated into `DREAMS.md` for human review and rollback tooling for backfills.

### Cited Findings
- "Dreaming is the background memory consolidation system in `memory-core`"; the page states "Dreaming is enabled by default", disable with `plugins.entries.memory-core.config.dreaming.enabled: false` — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md). The search-engine summary of the memory overview page said dreaming "is disabled by default" — [docs.openclaw.ai summary](https://docs.openclaw.ai/concepts/memory/index.html) — a conflict, probably between doc versions; the fetched pages both say default-on.
- Phases: **Light** "sorts and stages recent short-term material, dedupes signals, and writes a managed `## Light Sleep` block. It never writes to `MEMORY.md`"; **REM** "builds theme and reflection summaries and writes a `## REM Sleep` block"; **Deep** "scores and promotes durable candidates into `MEMORY.md`. It is the only phase with a durable write, and it writes a `## Deep Sleep` summary to `DREAMS.md`" — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Deep ranking weights: Relevance 0.30, Frequency 0.24, Query diversity 0.15, Recency 0.15, Consolidation 0.10, Conceptual richness 0.06; candidates must pass `minScore`, `minRecallCount`, `minUniqueQueries`; "Candidates with `untrusted` or `system` provenance are removed before consolidation" — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Promotion mechanics: "The model returns operation decisions (additions, merges, supersessions), not replacement prose. The writer applies them to the existing file"; a rewrite must keep prior entries within `phases.deep.maxPriorEntryLossFraction` (default 0.25), include each promoted candidate's source reference, fit the bootstrap-safe budget; on failure it falls back to append-only; entries get up to three concept tags and an importance 1–10; `phases.deep.maxPromotedSnippetTokens` default 160 — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Dream Diary: one narrative entry per useful sweep in `DREAMS.md`, generated with the agent's default model unless `dreaming.model` is set (requires `plugins.entries.memory-core.subagent.allowModelOverride: true`); "The diary is for human reading. It is not a promotion source"; optional reports at `memory/dreaming/<phase>/YYYY-MM-DD.md` — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Ingestion: "Only interactive sessions are eligible. Cron, heartbeat, subagent, and unknown sessions are excluded"; `memory forget` marks sessions `forgotten` — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Scheduling: one cron job `memory-core:memory-dreaming-promotion`; default `dreaming.frequency` `0 3 * * *`; `dreaming.timezone`; disabled when `cron.enabled: false` or `OPENCLAW_SKIP_CRON=1`; multi-agent fleets need `agents.defaults.systemAgent.agentId`; respects `agents.defaults.subagents.maxConcurrent` — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Operator controls: `/dreaming status|on|off|help` (on/off need owner or `operator.admin`); CLI `openclaw memory promote` (preview), `promote --apply`, `promote --limit 5`, `status --deep`, `promote-explain "<candidate>"`, `rem-harness --path <path> --grounded`, `rem-backfill --path <path> [--stage-short-term]`, `rem-backfill --rollback` / `--rollback-short-term`, `session-backfill --agent <id> [--apply|--rem|--rollback]` — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md). The docs cite arXiv:2504.13171 (sleep-time compute) as background — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md).
- Daily working layer feeding it: `memory/YYYY-MM-DD.md` notes "indexed for search, not injected every turn"; the pre-compaction flush writes only to the daily note — [OpenClaw memory](https://docs.openclaw.ai/concepts/memory.md).

### Inferences
- Dreaming is essentially a recall-driven promotion: what gets promoted is what `memory_search` keeps hitting (frequency, query diversity), not what the model judged important at write time — the opposite of Hermes/Claude Code, where importance is decided at write time.

### Gaps
- No version numbers or dates on the dreaming/memory docs; a third-party blog says the hybrid-search + dreaming docs appeared in October 2026 — [Supermemory blog](https://supermemory.ai/blog/why-everyone-is-complaining-about-openclaws-memory-it-sucks-and-why-supermemory-fixes-it/). Exact `minScore`/`minRecallCount`/`minUniqueQueries` defaults and the bootstrap budget size were not stated on the fetched pages.

## How does Hermes Agent's memory and self-improvement work?

### Takeaway
Hermes separates three durable stores — a tool-written `MEMORY.md`/`USER.md` pair injected as a frozen snapshot at session start, an FTS5 session archive searched on demand, and agent-authored `SKILL.md` files as procedural memory — and drives self-improvement with periodic in-session "nudges" plus a post-turn background review that can stage memory and skill edits behind optional human approval.

### Cited Findings
- See the Hermes profile above for files, limits, tool actions, snapshot injection, config keys and approval commands — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- Self-improvement loop for skills: the system prompt asks the agent to save non-trivial multi-step workflows, approaches that worked after errors, and user corrections; the agent patches skills "when it finds a better path"; a background review "can suggest or stage skill changes after a session"; writes can be gated by `skills.write_approval` and locked with `hermes curator lock <skill>` — [Hermes skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).
- The README frames it as "the agent creates skills on its own after complex tasks, and the skills improve as they are used", compatible with the agentskills.io standard, and "Honcho dialectic user modeling" for a "deepening model of who you are across sessions" — [Hermes README](https://github.com/NousResearch/hermes-agent); [Hermes docs home](https://hermes-agent.nousresearch.com/docs).
- Secondary descriptions of "periodic memory review" ("At set intervals during a session, the agent receives an internal system-level prompt asking it to look back ... and evaluate whether anything is worth persisting") — [mranand substack](https://mranand.substack.com/p/inside-hermes-agent-how-a-self-improving); the official docs name the knobs `memory.nudge_interval` and `skills.creation_nudge_interval` — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- A "Curator" "acts as a background librarian, organizing your agent's autonomously generated skills to prevent endless accumulation" — [anthonymaio substack (secondary)](https://anthonymaio.substack.com/p/getting-started-with-hermes-agent); the official skills page only references `hermes curator lock` and links a separate Curator page — [Hermes skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).
- Safety on learned content: memory entries scanned for injection/exfiltration patterns and invisible Unicode; `skills.guard_agent_created` scanner; hub installs security-scanned with `builtin`/`official`/`trusted`/`community` trust levels and `--force` cannot override a `dangerous` verdict — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory); [Hermes skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills).
- Benchmark claim circulating in secondary sources (agents with 20+ self-created skills complete similar tasks "40% faster") could not be verified against a primary Nous source — [turingpost](https://www.turingpost.com/p/hermes); [hermes-ai.net](https://www.hermes-ai.net/).

### Inferences
- The "frozen snapshot" design means Hermes deliberately trades mid-session freshness for prompt-cache stability; tool responses showing live state partially compensate.

### Gaps
- The Curator page itself was not fetched; details on how it merges or prunes skills are missing. No official release date for Hermes beyond the Product Hunt listing.

## What does LibreChat's memory agent look like (config keys, prompt, token limits, per-user opt-out)?

### Takeaway
LibreChat's memory is a per-user key/value store, injected whole under `# Existing memory about the user:`; the memory agent is an optional second agent (default `gpt-4.1-mini`) that runs concurrently with every request over the last `messageWindowSize` (5) messages, with hard `tokenLimit`/`charLimit`/`maxInputTokens` caps, admin-chosen `validKeys`, a default prompt that only saves on explicit "remember" requests, and a `personalize` flag deciding whether users may opt out.

### Cited Findings
- All config keys, defaults and the YAML example are listed in the LibreChat profile above — [LibreChat config docs](https://www.librechat.ai/llms.mdx/docs/configuration/librechat_yaml/object_structure/memory).
- Default prompt text and injection headers are quoted in the profile above — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- Per-user opt-out: "Reference saved memories" under Settings > Data & Privacy or the "Use memory" button; "The toggle appears only if the admin allows opt-out" (`personalize: true`) — [LibreChat memory docs](https://www.librechat.ai/llms.mdx/docs/features/memory); in source the opt-out is `personalization.memories === false` — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).
- Content filtering: "memory content is checked against `filters` before writing" and PII patterns can be active — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts).

### Inferences
- Because the agent's result is dropped if it outlasts the main response by 3 s, slow memory models silently stop saving — a likely source of "memory not saving" reports.

### Gaps
- The docs page lists `messageWindowSize` but the source summary says `processMemory` "applies no message window or count cap"; which layer applies the window could not be confirmed from the single file read.

## What UI patterns are used to show and manage memories?

### Takeaway
Three recurring patterns: (a) a browsable list of discrete entries with edit/delete and a usage/limit badge (ChatGPT "Manage memories", Claude "Topics", Copilot "Manage saved memories", LibreChat Memories panel, Open WebUI Personalization > Memory, AnythingLLM Memories sidebar with Move between scopes); (b) an editable prose summary with a pencil for custom instructions (Claude legacy, ChatGPT newer summary page); (c) raw files opened in an editor (Claude Code `/memory`, OpenClaw/Hermes markdown, Windsurf Customizations panel). Nearly all show an inline "memory updated/saved" event in the chat.

### Cited Findings
- ChatGPT: "a browsable list in Settings" (sort/search), and a newer summary page with "Delete and turn off memory" — [memx.app (third-party)](https://memx.app/blog/chatgpt-reference-chat-history-vs-saved-memories/).
- Claude.ai: Settings > Your Claude > Manage > Topics (read/edit/delete); legacy "Manage memory" modal with 24-hour summary and pencil icon; "See what Claude learned about you" button after import; "Tell Claude what to change or remove" box — [Claude Help Center](https://support.claude.com/en/articles/11817273); [Claude import/export](https://support.claude.com/en/articles/12123587-importing-and-exporting-your-memory).
- Copilot: "memory updated" notice; Settings > Personalization > Saved memories tile > Manage saved memories; Delete / Delete all — [Microsoft Support](https://support.microsoft.com/topic/b3231eae-9e60-4b3c-ac58-81fddbe56279).
- LibreChat: Memories side panel with key/value/agent filter, "Create Memory (+)", usage badge, "Saved memory"/"Deleted memory" steps grouped as "Ran 2 actions" — [LibreChat memory docs](https://www.librechat.ai/llms.mdx/docs/features/memory).
- Open WebUI: Settings > Personalization > Memory with view/add/edit/delete and clear-all; event previews truncated to 300 chars — [Open WebUI docs](https://docs.openwebui.com/features/chat-conversations/memory.md); [memories.py](https://raw.githubusercontent.com/open-webui/open-webui/main/backend/open_webui/routers/memories.py).
- AnythingLLM: Memories sidebar, + button, per-card three-dot Edit/Delete/Move, two toggles (Enable Personalization; Automatic Memory Extraction) — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).
- Claude Code: `/memory` lists files and toggles auto memory; "Saved 2 memories" / "Recalled 2 memories" messages — [Claude Code memory](https://code.claude.com/docs/en/memory).
- Hermes: `/memory pending|approve|reject`, `/skills diff <id>`, `/journey`; `display.memory_notifications` on/off/verbose — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).

### Inferences
- The discrete-entry list won over the prose summary (Claude moved from summary to Topics in 2026; ChatGPT keeps the list and adds a summary), because entries can be individually deleted and audited.

## Best-practice guidance on not remembering sensitive data and letting the user correct the model

### Takeaway
The clearest published policies are Claude's (sensitive categories off by default with per-save notices; some categories never stored even on request) and Copilot/ChatGPT's "only when the user clearly signals" framing; open-source apps mostly warn operators (AnythingLLM) or ship conservative default prompts (LibreChat) and give admins `validKeys`/filters; correction is universally "tell it in chat to update or forget" plus manual edit/delete.

### Cited Findings
- Claude: sensitive topics (health, race, ethnicity, religion, politics, gender identity) "Off by default"; opt-in with a notice per save; turning off removes already-saved items; "Never saved, even on request: government ID numbers, criminal history, financial account numbers, and immigration status"; also AUP-violating content — [Claude Help Center](https://support.claude.com/en/articles/11817273); [Anthropic blog](https://claude.com/blog/claudes-memory-works-everywhere-and-you-decide-whats-in-it).
- Claude correction: "tell Claude in chat to remember, change, or forget something. The change applies from your next conversation" — [Claude Help Center](https://support.claude.com/en/articles/11817273).
- ChatGPT enterprise: "PHI should not be entered when using this feature" (improved memory not under BAA); disabled by default in Healthcare/Regulated workspaces — [OpenAI Help](https://help.openai.com/en/articles/8411955-managing-workspace-settings-in-chatgpt-enterprise). Memory import prompts suggest editing out sensitive details before pasting — [Claude import/export](https://support.claude.com/en/articles/12123587-importing-and-exporting-your-memory).
- Copilot: saves "only when you clearly signal you want it remembered"; "admins can't restrict what type of information is added to Copilot memory" — [Tech Community](https://techcommunity.microsoft.com/t5/microsoft-365-copilot-blog/introducing-copilot-memory-a-more-productive-and-personalized-ai/ba-p/4432059); [Microsoft Learn](https://learn.microsoft.com/copilot/microsoft-365/copilot-personalization-memory).
- LibreChat default prompt: "NEVER store information just because the user mentioned it"; admins restrict categories with `validKeys` and content `filters`/PII patterns — [memory.ts](https://raw.githubusercontent.com/danny-avila/LibreChat/main/packages/api/src/agents/memory.ts); [LibreChat config docs](https://www.librechat.ai/llms.mdx/docs/configuration/librechat_yaml/object_structure/memory).
- AnythingLLM: "Don't store passwords, API keys, or sensitive personal data" because memory goes to the LLM provider in the system prompt — [AnythingLLM docs](https://docs.anythingllm.com/features/memories).
- Hermes: scans entries for injection/exfiltration and invisible Unicode; optional `memory.write_approval` human review — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).
- OpenClaw: untrusted/system-provenance candidates never promoted; untrusted files excluded from injection; "Memory informs behavior but does not enforce policy" — [OpenClaw dreaming](https://docs.openclaw.ai/concepts/dreaming.md); [OpenClaw memory](https://docs.openclaw.ai/concepts/memory.md).
- Claude Code: auto memory "skips anything it can derive from the codebase" and anything CLAUDE.md already says; corrections (`feedback` type) are first-class; a `modified` timestamp shows "how current the fact is" — [Claude Code memory](https://code.claude.com/docs/en/memory).
- Gemini: no personalization for Temporary Chats (72-hour retention), and the UK rollout excludes Business/Enterprise/U18 accounts — [9to5Google](https://9to5google.com/2025/08/13/gemini-personal-context/); [Google blog UK](https://blog.google/company-news/inside-google/around-the-globe/google-europe/united-kingdom/gemini-launches-new-personalisation-features-in-the-uk/).
- User-requested safeguards not yet common: an approve/reject step before auto-saves and bulk delete (ChatGPT community, Apr 2025) — [OpenAI community](https://community.openai.com/t/memory-management-system-creates-unwanted-memories-without-permission/1245049); Hermes is the only surveyed system with a built-in pending-approval queue — [Hermes memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory).

### Inferences
- A practical baseline that every surveyed product supports: global toggle that does not delete, per-chat opt-out (Temporary/Incognito/"Memory off"), delete-all, per-entry edit/delete, and "deleting a chat does not delete memories derived from it" stated explicitly (ChatGPT, Claude, Copilot).

### Gaps
- OpenAI's official wording on avoiding sensitive health data could not be retrieved (FAQ blocked); Open WebUI publishes no sensitive-data guidance in its memory doc.
