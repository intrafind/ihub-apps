## Proposal

### Shared CRM tool contract

The same names and shapes for every CRM, so an app like "Account briefing" works with any of them:

| Tool | Effect |
| --- | --- |
| `<crm>_searchRecords` | read: accounts/companies, contacts, opportunities/deals, cases/tickets, leads, by name, owner, stage, date |
| `<crm>_getRecord` | read: record with key fields, owner, related records and recent activities |
| `<crm>_listActivities` | read: notes, calls, emails, meetings, tasks for a record |
| `<crm>_createActivity` | write: note / task / call log linked to a record |
| `<crm>_updateRecord` | write: stage, amount, close date, owner, custom fields (confirmation shows before/after) |
| `<crm>_createRecord` | write: contact, lead, deal/opportunity |

### Dynamics 365 (Dataverse Web API)

- **Auth:** delegated OAuth through Entra ID with the environment URL as the resource (`https://<org>.crm*.dynamics.com/user_impersonation`). Dynamics security roles apply.
- **Queries:** OData `$filter`/`$expand`, or FetchXML for complex queries.
- **Schema:** entity metadata (`EntityDefinitions`) resolves custom fields and option sets to labels.

### HubSpot (CRM v3 API)

- **Auth:** per-user OAuth (public app registered by the customer), or a shared private-app token for read-only use.
- **Endpoints:** objects `companies`, `contacts`, `deals`, `tickets`; the Search API; associations (v4); engagements (notes, tasks, calls, meetings).
- **Pipelines:** pipeline and stage ids are resolved to labels.

### Safety

- All writes are confirmed; admin can make a CRM read-only.
- Output is limited to fields the admin allows, and the audit log records write actions.
