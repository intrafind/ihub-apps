Part of #EPIC. Builds on #FRAMEWORK.

## Summary

Give apps delegated access to Teams content:

- search and read channel and chat messages;
- pull meeting transcripts;
- after confirmation, post a message to a channel or chat.

This is different from #209, which puts iHub **inside** Teams as an app, bot or message extension. This issue makes Teams content available **to** iHub apps, and makes Teams a place to deliver results.

Typical requests:

- "What was decided in #project-x this week?"
- "Summarize yesterday's steering meeting and list the action items."
- "Post this summary to the team channel."

## Current state

- **Office 365 reads Teams files only.** The provider requests `Team.ReadBasic.All` and `Channel.ReadBasic.All` so it can list team document libraries in the file picker (`Office365Service.listTeamsDrives`). Messages, chats and meetings are not accessible.
- **Some Teams reads exist, app-only.** `EntraService.js` has `getTeamMembers` and `getTeamChannels`, using app-only credentials for people search.
- **No outbound channel.** Nothing can deliver a result to Teams. #2521 lists "Teams or webhooks" as a later notification channel.

## Proposal

### Tools

| Tool | Effect | Graph (delegated) |
| --- | --- | --- |
| `teams_searchMessages` | read | Microsoft Search API, `entityTypes: ["chatMessage"]` |
| `teams_listTeamsAndChannels` | read | `/me/joinedTeams`, `/teams/{id}/channels` |
| `teams_getChannelMessages` | read | channel messages + replies within a time window |
| `teams_listChats` / `teams_getChatMessages` | read | the user's 1:1 and group chats |
| `teams_listMeetings` | read | online meetings from the user's calendar (links to the calendar tools) |
| `teams_getMeetingTranscript` | read | `/me/onlineMeetings/{id}/transcripts/{id}/content` (VTT → speaker-attributed text) |
| `teams_postChannelMessage` | write | post or reply in a channel |
| `teams_sendChatMessage` | write | send in an existing chat |

### Scopes and consent

- Candidate delegated scopes, requested per enabled capability:
  - `ChannelMessage.Read.All`, `Chat.Read` and `OnlineMeetingTranscript.Read.All` for reading;
  - `ChannelMessage.Send` and `ChatMessage.Send` for posting.
- Several of these need **admin consent**. The admin page must say which capability needs which scope.
- Use delegated permissions only. The user sees exactly what they can see in Teams, and we stay away from the protected application-permission APIs.

### Results delivery

Besides being a tool, "post to Teams channel" becomes a delivery target:

- for scheduled tasks (#2521), as a notification channel;
- for workflows, as a node or tool.

A shared connection (#FRAMEWORK) could post through a bot identity instead of a user. That depends on the bot work in #209.

### Safety

- **Posting always confirms,** showing the target team, channel or chat and the rendered message.
- **Message and transcript content is untrusted input** (prompt injection).
- **Transcripts can be long:** cap the size, and let the model page through large ones or summarize them first.

## Acceptance criteria

- [ ] Search, channel, chat and transcript tools work with the user's delegated token and return only content the user can see.
- [ ] Posting to channel/chat requires confirmation; admin can disable posting.
- [ ] Scopes are requested per enabled capability; admin docs list consent requirements.
- [ ] "Post to Teams" usable as a delivery target for scheduled tasks and workflows.
- [ ] Example app "Meeting recap" (transcript → summary + action items; optional hand-off to the Planner/To Do or Jira tools).
- [ ] Tests with mocked Graph; docs; changelog entry.
