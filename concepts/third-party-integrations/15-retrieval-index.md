## Summary

Some customers already run their own retrieval index, built by a data team or left over from an earlier RAG project. Today they cannot use it in iHub without moving the content. Add a read-only source/tool type that queries such an index and feeds the hits into the existing grounding and citation flow.

iFinder remains the recommended enterprise search. This covers customers with an existing index, and gives them a migration path.

## Current state

- **Source types:** filesystem, URL, iFinder and page (`server/sources/`: `FileSystemHandler.js`, `URLHandler.js`, `IFinderHandler.js`, `PageHandler.js`).
- **No embedding model configuration exists.** Model configs cover chat/completion models only. A vector query needs the query embedded with the **same** model that built the index.
- **Citations:** the citation and grounding UI is tracked in #1466.

## Proposal

### Index connections (admin)

- **Engines:** Qdrant, Milvus, Pinecone, Azure AI Search and Elasticsearch/OpenSearch. Weaviate and Vertex AI Vector Search can come later.
- **Connection settings:** endpoint URL, credential reference (API key via the credential store), index or collection name.
- **Query vectorization:** one of two modes:
  - **index-side:** the engine embeds the query itself (Azure AI Search integrated vectorization, Elasticsearch/OpenSearch inference, Qdrant/Weaviate server-side inference), or
  - **iHub-side:** embed with a configured embedding model. This needs a small "embedding model" config: provider, model, dimensions. OpenAI-compatible and Azure endpoints first.
- **Field mapping:** text/content, title, URL, document id, page/chunk number, metadata fields exposed to filters.
- **Search mode:** vector, keyword or hybrid where the engine supports it; `topK`; score threshold.
- **Filters:**
  - static filters set by the admin, for example `language = de`;
  - optional model-provided filters on allowed metadata fields, for example year or department.

### Permissions

- Group-based access per index source, as for other sources.
- **Optional security trimming:** if the index stores ACLs in a metadata field (for example `allowed_groups`), iHub adds a filter with the user's groups on every query. Without this, every user of the source sees the whole index, and the admin UI says so clearly.

### Use in apps

- **As a source** (`type: "vectorIndex"`): retrieved on each turn, like the existing sources.
- **As a tool** (`vectorIndex_search`): the model decides when to search and with which query and filters.
- **Hits become citations** with title, URL and chunk text.

### Out of scope for v1

Writing to or indexing into these engines (upsert). iHub stays a consumer.
