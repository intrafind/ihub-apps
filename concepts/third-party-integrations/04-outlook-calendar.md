## Summary

Let apps read and manage the user's Outlook calendar through Microsoft Graph, with the user's own permissions. Typical requests:

- "What's on tomorrow?"
- "Find 30 minutes with Anna and Ben next week."
- "Move my 1:1 to Thursday afternoon."
- "Prepare me for my next meeting." This one combines calendar, mail, Jira and CRM tools.

## Current state

- **No calendar access.** The Office 365 provider (`Office365Service.js`) requests only file-related scopes (`_buildScopes`), and no calendar tools exist.
- **Colleagues can already be resolved.** `entraPeopleSearch` (`server/tools/entraPeopleSearch.js`, `EntraService.js`) turns a name into an email address, with app-only credentials. Attendee lookup can reuse it.
- **Relative dates are covered.** Chat requests already carry temporal context (current date and time; see `server/tests/chat-temporal-context.test.js`), which the model needs to resolve "next Tuesday".

## Proposal

### Tools

| Tool | Effect | Graph |
| --- | --- | --- |
| `outlook_listEvents` | read | `GET /me/calendarView?startDateTime=&endDateTime=`, in the user's timezone (`Prefer: outlook.timezone`) |
| `outlook_getEvent` | read | details, attendees and responses, online meeting link, body as text |
| `outlook_getSchedule` | read | `POST /me/calendar/getSchedule`: free/busy for colleagues |
| `outlook_findMeetingTimes` | read | `POST /me/findMeetingTimes`: attendees, duration, time window, working hours |
| `outlook_createEvent` | write | subject, start/end, attendees, location, body, optional Teams meeting (`isOnlineMeeting`) |
| `outlook_updateEvent` | write | reschedule, change attendees or body |
| `outlook_respondToEvent` | write | accept / tentatively accept / decline, with a comment |
| `outlook_cancelEvent` | destructive | cancel with a message to attendees (organizer only) |

### Scopes

- Request calendar scopes only when the capability is enabled:
  - read-only → `Calendars.Read`;
  - create and update → `Calendars.ReadWrite`.
- Free/busy and find-meeting-times need the scopes their Graph endpoints require. Confirm the least-privileged scope for each endpoint against the Graph permissions reference during implementation.
- Scopes are added to the existing Office 365 provider through the scope upgrade flow in #FRAMEWORK.

### Safety and UX

- **Confirmation card before any write.** It shows the resolved absolute date and time (with timezone), the attendees (name and email) and the Teams-meeting flag. Invitations are sent to other people, so a write is never silent.
- **Timezone:** the user's IANA timezone from the browser, passed with each call. Results are shown in that zone.
- **Attendee resolution:** names are resolved through Entra people search. If a name is ambiguous, the tool asks the user through `ask_user` instead of guessing.

## Acceptance criteria
