## Summary

Many useful integrations are small: a REST API, one API key, two or three read operations. They don't need custom code. The OpenAPI tool runner can already run them, but every admin has to find or write the OpenAPI document, trim it, and configure tools and credentials by hand.

Ship **installable tool packages** instead: a trimmed OpenAPI document, tool definitions with good descriptions, a credential placeholder and an example app. Start with services that fit our customers:

- **German commercial register lookup** through a register data provider (for example OpenRegister or North Data). Search companies, register number, legal form, address, managing directors, shareholders. Useful for sales research, supplier checks and KYC-like processes.
- **Geocoding, places and distances** (for example Google Maps Platform, or an EU alternative such as HERE or a self-hosted Nominatim/OSRM). Examples: "How far is the site from our Munich office?", "Find hotels near the venue".
- **Market and statistics data** for customers that license it (for example Statista). Search statistics and retrieve a statistic by id, with source attribution.

## Current state

- **The runner is shipped.** `type: "openapi"` tools (#1462) landed with `OpenApiToolRunner.js`, `OpenApiToolEditor.jsx`, `openApiToolDefSchema.js` and the central credential store `CredentialService`.
- **Marketplace packaging was deferred.** #1462 notes that the marketplace `ContentInstaller` `tool` dispatch type was left for a follow-up (`server/services/marketplace/ContentInstaller.js`). Tool packages can therefore not be installed from a registry yet.

## Proposal

### 1. Marketplace tool packages

- Extend `ContentInstaller` with a `tool` package type. A package can contain:
  - one or more `type: "openapi"` tool definitions;
  - the OpenAPI document, stored under `contents/` and referenced as a `file` source;
  - a credential **placeholder**, created empty for the admin to fill in, and never shipped with secrets;
  - optionally an example app that uses the tools.
- **Install flow:** install → the admin is taken to the credential form → a "Test" button runs a sample operation.
- **Uninstall** removes the tools and the document, and asks before removing the credential.

### 2. Curated packages

For each package:

- the OpenAPI document is trimmed to the operations we need;
- `xDisplay.hideFields` strips noise from responses;
- descriptions are written for the model (when to use the tool, parameter formats);
- the package README covers cost, rate limits and the data-protection notes for the provider.

### 3. Package authoring guide

A short doc explaining how to turn any API-key REST service into a package. This lets customers and partners add services we don't curate.
