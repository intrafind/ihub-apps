## Summary

For customers on Slack instead of Teams, give apps the same kind of access:

- search messages;
- read channel history and threads;
- look up people;
- after confirmation, post a message or a thread reply.

Slack also becomes a place to deliver results from scheduled tasks and workflows.

## Current state

- **No Slack integration.** The only reference is a placeholder comment in `client/src/features/chat/hooks/useIntegrationAuth.js`.
- **No outbound messaging channel exists.** See #2521 on notifications.

## Proposal

### Tools

| Tool | Effect | Slack Web API |
| --- | --- | --- |
| `slack_searchMessages` | read | `search.messages` (needs a **user** token with `search:read`) |
| `slack_listChannels` | read | `conversations.list` (public/private channels the user is in) |
| `slack_getChannelHistory` | read | `conversations.history` within a time window |
| `slack_getThread` | read | `conversations.replies` |
| `slack_lookupUser` | read | `users.info` / `users.lookupByEmail` |
| `slack_postMessage` | write | `chat.postMessage` to a channel or thread, as the user (user token) or the app (bot token) |

### Auth

- **Per-user OAuth v2 with user-token scopes:** `search:read`, `channels:history`, `groups:history`, `im:history`, `mpim:history`, `channels:read`, `groups:read`, `users:read`, `users:read.email` and `chat:write`. The model sees what the user sees.
- **Optional shared bot token (#FRAMEWORK shared connection)** for posting results from scheduled tasks and workflows into fixed channels.
- **Each customer registers its own internal Slack app,** as with Jira and Office 365. Slack applies stricter rate limits to commercially distributed apps that are not in the Slack Marketplace. Verify the current rules before implementation.

### Safety

- Posting always confirms (channel, thread, rendered message). Admin can disable posting, or limit it to allowed channels.
- Message content is untrusted input.
- Mentions (`@channel`, `@here`) are stripped from model-generated posts unless the admin allows them.

## Acceptance criteria

- [ ] Search, channel history, thread and user lookup work with the user's token and return only what the user can see.
- [ ] Posting requires confirmation; optional channel allow-list; mass-mention stripping.
- [ ] Shared bot connection usable as a delivery target for scheduled tasks and workflows.
- [ ] Rate-limit handling (`Retry-After`) and pagination (`cursor`).
- [ ] Tests with mocked Slack API; docs incl. Slack app setup; changelog entry.
