## Summary

Let apps read and manage the user's tasks in Microsoft To Do (personal) and Microsoft Planner (team plans) through Graph, with the user's own permissions. This closes the loop for use cases like:

- "Turn the action items from this meeting into Planner tasks and assign them."
- "What's due this week?"
- "Add a reminder to follow up with the supplier on Friday."

## Current state

- **No task tools.** The Office 365 provider requests file scopes only, and no Planner or To Do tools exist.
- **Name clash.** The names `create_task`, `list_tasks` and `mark_task_done` are already taken by the agent run-queue tools in `server/defaults/tools/`. The new tools need a prefix.
- **Assignees can be resolved** from names to user ids with `entraPeopleSearch` (`EntraService.js`).

## Proposal

### Tools

| Tool | Effect | Graph |
| --- | --- | --- |
| `todo_listLists` | read | `/me/todo/lists` |
| `todo_listTasks` | read | tasks of a list, filtered by status and due date |
| `todo_createTask` | write | title, body, due date, reminder, importance, linked resource (for example a link back to the chat) |
| `todo_updateTask` | write | edit, complete, reopen |
| `planner_listPlans` | read | plans of the user's groups (`/me/planner/plans`) |
| `planner_listTasks` | read | tasks by plan or bucket, or assigned to the user (`/me/planner/tasks`) |
| `planner_createTask` | write | plan, bucket, title, due date, assignees, checklist, description |
| `planner_updateTask` | write | progress, assignees, due date. Planner requires the `If-Match` ETag, so the tool reads it first. |

### Scopes

- `Tasks.ReadWrite` (or `Tasks.Read` for read-only) covers To Do and the user's Planner tasks.
- Listing group plans may additionally need `Group.Read.All` (admin consent). Confirm this against the Graph permissions reference during implementation.
- Scopes are added to the Office 365 provider through the scope upgrade flow (#FRAMEWORK).

### UX

- **Bulk creation confirms once.** Creating tasks from a meeting transcript is usually a batch, so the confirmation card lists all proposed tasks (title, assignee, due date) as an editable table. The user approves them in one step.
- **Each created task links back** to the originating chat when chat sharing or persistence is available.
