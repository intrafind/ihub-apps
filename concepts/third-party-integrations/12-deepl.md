## Summary

Translation is one of the most used use cases among our (largely German-speaking) customers. Today it runs through the LLM only. Add DeepL as a translation engine, for four things an LLM does not do reliably:

- **Glossaries:** enforced terminology per language pair, for product names, legal terms and the authority's own vocabulary.
- **Document translation that keeps the layout** of DOCX, PPTX, XLSX and PDF. The user gets the translated file back, not text.
- **Deterministic, fast, cheap bulk translation.** No model tokens, and no drift in style between runs.
- **EU data processing** with DeepL API Pro (texts are not stored), which many public-sector customers require.

## Current state

- **No DeepL integration.** The `deepl` matches in the code are all "deep link".
- **Translation apps are prompt-based,** running on whichever model the app uses.
- **Admin credentials already exist.** The central credential store (`CredentialService`, types `apiKeyHeader`/`secret`) can hold a shared API key.

## Proposal

### Connection

- A shared connection (#FRAMEWORK) holding an admin API key. Optionally, users bring their own key.
- The key determines the endpoint: DeepL API Free (`api-free.deepl.com`) or Pro (`api.deepl.com`).

### Tools

| Tool | Effect | DeepL API |
| --- | --- | --- |
| `deepl_translateText` | read | `/v2/translate`: source (auto) / target language, `formality`, `glossary_id`, `context`, `tag_handling` (HTML/XML) for formatted text |
| `deepl_translateDocument` | read | `/v2/document` upload → poll status → download; the translated file is attached to the chat as a downloadable file |
| `deepl_improveText` | read | `/v2/write/rephrase` (DeepL Write, Pro): style/tone; supported languages only |
| `deepl_listGlossaries` | read | available glossaries with language pairs |
| `deepl_getUsage` | read | character usage vs limit (admin) |

### Translation engine setting (no model in the loop)

- A translator app can set `translation.engine: "deepl"`. The app then sends the user's text or file straight to DeepL and shows the result, without a model call.
- The model stays optional for post-processing, for example "explain the changes".
- Workflows get a "Translate (DeepL)" node for pipelines such as "translate every incoming document to German".

### Glossary management (admin)

- `/admin/integrations/deepl`: create, upload (CSV/TSV) and delete glossaries per language pair, and bind a default glossary to an app.
- DeepL glossaries are immutable. "Edit" therefore means create a new glossary and swap the id, handled transparently.

### Usage

- Character counts go into the usage tracker with `source: deepl`, so admins can see the cost next to model tokens.
- Show a warning when the monthly quota is close.

## Acceptance criteria

- [ ] Text translation with auto source detection, formality, glossary and HTML tag handling.
- [ ] Document translation for DOCX, PPTX, XLSX, PDF, HTML and TXT, returned as a downloadable file in chat; progress shown while DeepL processes.
- [ ] DeepL Write rephrasing where the language is supported.
- [ ] Apps can use DeepL as translation engine without a model call; workflow node available.
- [ ] Admin glossary management (CSV upload, per language pair, default glossary per app).
- [ ] Free vs Pro endpoint selected by key; usage tracked; quota warning.
- [ ] Language code mapping (e.g. `EN-GB`/`EN-US`, `PT-BR`/`PT-PT`) handled.
- [ ] Tests with mocked API; docs; changelog entry.
