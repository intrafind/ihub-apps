## Summary

For customers on Google Workspace, offer what the Microsoft 365 issues offer for Outlook:

- **Gmail:** search, read, draft, and send after confirmation;
- **Google Calendar:** schedule, free/busy, create and update events after confirmation;
- **Docs, Sheets and Slides:** read content live, and append or update Sheets rows after confirmation.

## Current state

- **Google Drive connects for file picking only,** with `drive.readonly`, `userinfo.profile` and `userinfo.email` (`GoogleDriveService.js`). Google Docs and Slides are exported to PDF and Sheets to XLSX when picked.
- **No Gmail, Calendar or Sheets tools exist.**

## Proposal

### Tools

| Tool | Effect | API |
| --- | --- | --- |
| `gmail_search` | read | Gmail `users.messages.list` with Gmail query syntax |
| `gmail_getMessage` / `gmail_getThread` | read | body as text, headers, attachments list |
| `gmail_getAttachment` | read | shared server-side extractor |
| `gmail_createDraft` | write | new / reply (thread-aware) |
| `gmail_sendDraft` | destructive | off unless enabled by the admin |
| `gcal_listEvents` | read | `events.list` in the user's timezone |
| `gcal_freeBusy` | read | `freebusy.query` |
| `gcal_createEvent` / `gcal_updateEvent` | write | with optional Meet link |
| `gdocs_getDocument` | read | Docs API → markdown (headings, lists, tables) instead of the PDF export |
| `gsheets_getValues` | read | range read with header detection |
| `gsheets_appendRows` / `gsheets_updateValues` | write | confirmation shows the affected range and values |
| `gslides_getPresentation` | read | slide text and speaker notes |

### Scopes and verification

- Request scopes per enabled capability:
  - `gmail.readonly`, `gmail.compose` and `gmail.send`;
  - `calendar.readonly` and `calendar.events`;
  - `documents.readonly`, `spreadsheets` and `presentations.readonly`.
- Several Gmail and Drive scopes are **restricted** or **sensitive**. They need Google app verification when the OAuth app is external. A customer registering an **internal** OAuth app in its own Workspace avoids this, the same as the Google Drive setup today. The docs must say so.

### Provider-neutral contracts

Mail and calendar tools should share parameter and result shapes with the Outlook tools. That allows an optional provider-neutral layer (`mail_*`, `calendar_*`) that routes to whichever provider the user connected (see the open questions in the Outlook issues).

## Acceptance criteria

- [ ] Gmail search/read/draft (send optional, confirmed); Calendar list/free-busy/create/update (confirmed); Docs/Slides read as text; Sheets read and write (confirmed).
- [ ] Scopes requested per enabled capability; existing Google Drive users prompted to reconnect.
- [ ] Setup docs cover internal OAuth app vs verification requirements.
- [ ] Result shapes aligned with the Outlook Mail/Calendar tools.
- [ ] Tests with mocked Google APIs; `docs/google-drive-integration.md` extended or a new Google Workspace page; changelog entry.

## Open questions

2. Should the provider-neutral layer come first, so apps don't need a Google and a Microsoft variant?
