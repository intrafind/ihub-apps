## Summary

Confluence is where many of our customers keep processes, project docs and meeting notes. Let apps work with it as the user:

- search Confluence and read pages and comments;
- after confirmation, create pages, update pages and add comments;
- on Atlassian Cloud and on self-hosted Data Center.

Typical requests:

- "What's our travel expense process?"
- "Write the meeting notes into the project space under Meetings."
- "Update the release page with today's status."

## Current state

- **No Confluence integration.** The only Atlassian integration is Jira, and it supports Cloud only: OAuth 2.0 (3LO) through `auth.atlassian.com`, API calls through `api.atlassian.com/ex/jira/{cloudId}` (`JiraService.js`, `docs/JIRA_INTEGRATION.md`). The same Atlassian OAuth app can be granted Confluence scopes.
- **Search is possible through iFinder where it is set up.** Customers whose iFinder indexes Confluence can already search it (see `server/defaults/skills/ifinder-search/`). What they cannot do is read live content with per-user permissions, write pages, or search Confluence at all without iFinder.

## Proposal

### Tools

| Tool | Effect | Notes |
| --- | --- | --- |
| `confluence_search` | read | CQL (`text ~`, `space`, `type`, `lastmodified`, `label`); the model can build CQL from natural language |
| `confluence_getPage` | read | body converted from storage format to markdown; title, space, version, author, last modified, ancestors, labels, `webui` link, attachment list |
| `confluence_getPageChildren` | read | page tree navigation |
| `confluence_listSpaces` | read | spaces the user can see |
| `confluence_getComments` | read | footer and inline comments |
| `confluence_getAttachment` | read | download and extract text with the shared server-side extractor (see the cloud storage file tools issue) |
| `confluence_createPage` | write | space, parent page, title, markdown body → storage format |
| `confluence_updatePage` | write | version-checked update (increments `version.number`); confirmation card shows a diff |
| `confluence_addComment` | write | footer comment on a page |

### Deployments and auth

- **Cloud:** Atlassian OAuth 2.0 (3LO) with Confluence scopes, sharing the Atlassian client config with Jira.
  - Pick classic or granular scopes consistently.
  - Use REST v2 where it covers the endpoints we need, and v1 for CQL search.
- **Data Center:** a base URL plus per-user **personal access tokens**, or OAuth 2.0 application links where the version supports them. The self-hosted URL goes through the SSRF guard.
- **One connector definition covers both.** The API differences (endpoints, v1/v2) stay inside the connector.

### Chat actions

- A "Save as Confluence page" action on assistant messages opens the create-page confirmation with the message content pre-filled.
- Page links in answers are citations that open Confluence.

## Acceptance criteria

- [ ] Search, read page, children, spaces, comments and attachments work as the user on Cloud and Data Center.
- [ ] Create page, update page (with version check and diff preview) and add comment require confirmation.
- [ ] Storage format ↔ markdown conversion handles headings, lists, tables, code blocks, links and macros (unknown macros are kept as-is on update).
- [ ] Atlassian OAuth config is shared with Jira; Data Center via base URL + PAT.
- [ ] "Save as Confluence page" message action.
- [ ] Tests with mocked Cloud and DC APIs; `docs/` page + SUMMARY entry; changelog entry.

## Open questions

1. Should Confluence spaces also be usable as a synced knowledge **source** (like #410 for SharePoint), or do we leave indexing to iFinder?
2. Should `updatePage` allow replacing a whole page, or only appending and editing sections, to limit the damage a bad edit can do?
