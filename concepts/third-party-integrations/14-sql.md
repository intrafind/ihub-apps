## Summary

A lot of company knowledge sits in relational databases: ERP extracts, reporting marts, case-management systems, data warehouses. Let an admin connect a database, describe it, and give it to an app. Users can then ask questions in plain language. The model:

- explores the schema;
- writes a **read-only** query;
- runs it under strict guardrails;
- answers with the result as a table or chart, and shows the SQL it ran.

## Current state

- **No database connectivity.** No tool, source or workflow node exists for it. The workflow `HttpNodeExecutor` covers HTTP APIs only.
- **Credentials can be stored.** The central credential store (`CredentialService`) holds admin-owned secrets (`basic`, `secret`, …) that a database connection can reference.
- **Binary size matters.** The server is also shipped as a single executable (`build-sea.sh`), so new native drivers affect its size.

## Proposal

### Database connections (admin)

- **Supported engines in v1:** PostgreSQL, Microsoft SQL Server, MySQL/MariaDB and Oracle. These cover most on-prem customers.
- **Warehouses as follow-up drivers:** Snowflake, Google BigQuery and Databricks SQL.
- **Connection settings:** host, port, database, TLS options, and a credential reference. **The credential must be a read-only database user**, and the docs say so plainly.
- **Allowed schemas and tables** per connection, as an allow-list.
- **Column policy:** a deny-list, or explicit PII columns that are never selected or are masked in results.
- **Semantic notes:** descriptions for tables and columns, business terms ("an active customer is …"), and example questions paired with example SQL. These go into the tool context.

### Tools (per connection)

| Tool | Effect | Notes |
| --- | --- | --- |
| `sql_listTables` | read | allowed tables with descriptions and row-count estimates |
| `sql_describeTable` | read | columns, types, keys, descriptions, a few sample values (masked for PII columns) |
| `sql_query` | read | executes one SELECT; returns rows (capped), column types, truncated flag |

### Guardrails, in layers

1. The DB user is read-only. This is the primary control.
2. A SQL parser check: one statement only, `SELECT`/`WITH` only, no DDL/DML, no `INTO`, no engine-specific escapes (`COPY`, `xp_`, `LOAD_FILE`, …). Only allowed tables may be referenced.
3. A statement timeout and a row cap (`LIMIT`/`TOP` injected), plus a result size cap.
4. Denied columns are rejected. Masked columns are masked in the output.
5. Every query is written to the audit log (user, connection, SQL, row count, duration). Result data is not logged.

### Answers

- Results render as tables, with an optional chart through the existing renderers.
- Results can be downloaded as CSV.
- The executed SQL is shown, collapsed, with every answer.
- A failed query returns the database error to the model for a bounded number of self-corrections.

### Access

- The database connection is shared (#FRAMEWORK), and group permissions decide who may use which connection.
- Optional: pass the user's identity to the database (for example Postgres `SET app.user_id`, SQL Server `SESSION_CONTEXT`) so row-level security policies in the database can apply.

### Dependencies

- Drivers (`pg`, `mssql`, `mysql2`, `oracledb`) load lazily as optional dependencies, so installations without databases don't pay for them.
- Check the impact on the single-executable build.

## Acceptance criteria

- [ ] Admin can create, test and describe connections for PostgreSQL, SQL Server, MySQL/MariaDB and Oracle; credentials via the credential store.
- [ ] Table allow-list, column deny/mask policy, semantic notes and example queries per connection.
- [ ] `listTables`, `describeTable` and `query` tools with parser check, timeout, row cap and audit log.
- [ ] Answers show SQL, render tables/charts, allow CSV download.
- [ ] Group-based access per connection; optional user identity passed for database RLS.
- [ ] Security tests for the parser check (multi-statement, DML, comments, engine-specific escapes); docs incl. "create a read-only user" recipes per engine; changelog entry.
