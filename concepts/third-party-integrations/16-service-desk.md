## Summary

IT helpdesks and customer-support teams are among the heaviest users of AI assistants. Give apps access to the two most common service-desk platforms, as the signed-in agent or employee, so they can:

- search tickets/incidents and knowledge articles;
- read a ticket with its conversation;
- find similar solved tickets;
- draft a reply or work note;
- after confirmation, create or update tickets.

Typical requests:

- "Summarize INC0012345 and suggest a solution from similar incidents."
- "Draft a reply to this customer based on our help-center article."
- "Open an incident: VPN not working for the Munich office."

## Current state

- **No service-desk integration exists.** The closest is Jira (`server/tools/jira.js`), which some customers use as a service desk (Jira Service Management).

## Proposal

### ServiceNow

- **Auth:** per-user OAuth 2.0 authorization code, with the customer's instance as the OAuth provider. ServiceNow ACLs apply. An admin-shared integration user is possible for read-only knowledge search.
- **Tools** (Table API, `/api/now/table/...`):

| Tool | Effect | Notes |
| --- | --- | --- |
| `servicenow_searchRecords` | read | incidents, requests (`sc_req_item`), problems, changes, tasks, with encoded query |
| `servicenow_getRecord` | read | record, work notes, comments, related CI |
| `servicenow_searchKnowledge` | read | `kb_knowledge` articles (published, user can read) |
| `servicenow_createIncident` | write | short description, description, caller, category, CI, urgency/impact |
| `servicenow_updateRecord` | write | add work note (internal) or comment (customer-visible), change state or assignment group |

### Zendesk

- **Auth:** per-user OAuth, or a shared API token for read-only help-center access.
- **Tools:**

| Tool | Effect | Notes |
| --- | --- | --- |
| `zendesk_searchTickets` | read | Search API (`type:ticket status:solved …`) |
| `zendesk_getTicket` | read | ticket with comments (public and internal) |
| `zendesk_searchArticles` | read | Help Center articles |
| `zendesk_createTicket` | write | subject, description, requester, priority, tags |
| `zendesk_updateTicket` | write | public reply vs internal note, status, assignee, tags |

### Safety

- **Customer-visible replies need extra care.** The confirmation card clearly separates "internal note" from "public reply to the customer", and public replies can be disabled by the admin.
- **Ticket content is untrusted input** (customer-written text).

### Triggers (with the triggers issue)

"New incident in assignment group X" or "new ticket with tag Y" can start a triage workflow: categorize, suggest a KB article, draft a first reply as an internal note.

## Acceptance criteria

- [ ] ServiceNow: search/get records, knowledge search, create incident, update with work note/comment/state, as the user (OAuth) with ACLs respected.
- [ ] Zendesk: search/get tickets, help-center search, create/update with explicit internal-vs-public distinction.
- [ ] All writes confirmed; public replies can be disabled.
- [ ] Example app "Service desk copilot" (disabled by default).
- [ ] Tests with mocked APIs; docs incl. OAuth setup on each platform; changelog entry.
