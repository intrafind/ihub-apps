## Summary

Many of our customers keep their business figures in Power BI. Let apps answer questions such as "How did revenue in region South develop in Q3 compared with last year?". The model:

- finds the right semantic model (dataset);
- reads its tables, columns and measures;
- runs a read-only DAX query through the Power BI REST API, **as the user**, so row-level security applies;
- returns the result as a table or chart.

## Current state

- **No BI or analytics integration exists.** Answers over structured business data are only possible by uploading exports.
- **Rendering is ready.** Results can use the existing renderer and artifact pipeline (tables, charts through custom renderers).

## Proposal

### Tools

| Tool | Effect | Power BI REST API |
| --- | --- | --- |
| `powerbi_listWorkspaces` | read | `GET /groups` |
| `powerbi_listDatasets` | read | datasets in a workspace, with description |
| `powerbi_getModelSchema` | read | tables, columns, measures (with descriptions) of a dataset |
| `powerbi_executeQuery` | read | `POST /datasets/{id}/executeQueries` with a DAX `EVALUATE` query; row cap |
| `powerbi_listReports` | read | reports and their pages, with `webUrl` so the answer can link to the report |

### Auth

- Delegated OAuth against Entra ID with the Power BI service resource (`https://analysis.windows.net/powerbi/api/…`): `Dataset.Read.All`, `Report.Read.All`, `Workspace.Read.All`.
- It can reuse the Office 365 / Entra app registration.
- The tenant admin must enable the "Dataset Execute Queries REST API" tenant setting. The admin page checks this and shows it.

### Making DAX reliable

- **Schema retrieval:** use `INFO` DAX functions where the user has permission. Otherwise fall back to an admin-curated schema description per dataset.
- **Admin-curated context per dataset:** a description, example questions and example DAX queries, in the style of a "semantic layer lite".
- **Query guardrails:**
  - only `EVALUATE` statements;
  - an enforced `TOPN` row cap;
  - a timeout;
  - failed queries return the DAX error, so the model can fix the query itself within a bounded number of retries.
- **Every answer shows the DAX it ran** (collapsible), so users can verify the numbers.

## Acceptance criteria

- [ ] List workspaces, datasets and reports visible to the user; schema tool returns tables/columns/measures.
- [ ] `executeQuery` runs read-only DAX with a row cap and timeout, as the user (RLS honoured).
- [ ] Admin can attach descriptions and example queries per dataset.
- [ ] Answers show the executed query and link to the matching report when known.
- [ ] Docs incl. the required tenant setting; changelog entry.
